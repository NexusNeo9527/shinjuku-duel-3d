# v0.2.14 主页触屏全屏修复

用户在 iOS Edge 中反馈主页全屏按钮没有响应。检查发现，旧实现等待原生 `requestFullscreen()` 请求完成后才启动回退；模拟原生请求一直挂起时，主页按钮始终保持未选中，页面未进入铺满模式。

## 行为修正

- 触屏和触控笔通过 `pointerup` 直接触发，鼠标及键盘仍使用 `click`，抑制同一次触屏产生的重复点击。
- 点击时立即进入页面铺满模式并更新图标、选中边框及辅助状态，再在同一次用户操作中尝试原生全屏。
- 回退定时器不再依赖原生 Promise 完成；接口缺失、禁用、拒绝、返回成功却未进入全屏、一直挂起都不会造成按钮无响应。
- 用请求序号隔离旧请求；退出后的迟到成功或迟到拒绝不重新打开全屏，原生退出事件同步按钮状态。
- 全屏按钮在触屏设备上至少为 44×44 CSS 像素。不支持原生全屏时提示“已铺满页面 · 浏览器地址栏可能仍保留”。

## 验证

- 已安装的 Windows Chrome 和 Microsoft Edge：主页和战斗中的真实触控进入/退出原生全屏，以及键盘激活和原生退出事件。
- 两个浏览器各验证 10 种场景（原生、缺失、禁用、拒绝、无实际效果、一直挂起、迟到成功、迟到拒绝、WebKit 前缀、兼容 click 被拦截），覆盖主页和战斗，共 40 个用例。
- iOS Edge 用户代理及 WebKit 行为通过模拟验证；未把 Chromium 的用户代理模拟当作实体 iOS Edge 或 Safari 验收。微信内置浏览器的受限接口场景采用同样的模拟覆盖。
- 22 个角色、140 组技能页布局复测未发现新遮挡或脚本异常。
- 扩大全屏按钮后，九种视口的 846 次页面控件布局检查通过。
- 全部 16 个现有回归套件、生产构建及差异格式检查通过。

原生全屏依赖浏览器支持与用户激活；页面铺满模式不能强制隐藏浏览器自己的地址栏。参考：[MDN requestFullscreen](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen)。
